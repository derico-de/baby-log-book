# Feeding defaults: preselect mode and bottle contents

Type: task
Category: enhancement
Status: resolved

## Request (from the dev, 2026-08-18)

> Allow defining defaults for feeding:
>
> - Breast
> - Bottle >
>   - Breast milk
>   - Formula
> - use buttons for contents, directly under Breast/Bottle/Food switch.

## What this means

The feed sheet today always opens on **Breast**, and bottle contents default to
`breast_milk` behind a `<select>`. For a formula-fed baby every single bottle
costs two extra corrections at 3am.

Two changes:

1. **A configurable default** for the sheet's starting state: which mode
   (Breast / Bottle) opens preselected, and for Bottle, which contents
   (`breast_milk` / `formula`).
2. **Contents become a segmented button row** (like the existing Left / Right /
   Both row for breast side), placed directly under the Breast / Bottle / Food
   switch — replacing the `<select>` further down the sheet. One glance, one
   tap, no dropdown.

## Decisions (triage, 2026-08-18)

- **The default is a Device Setting** — localStorage beside appearance and the
  install-banner flag, never in the sync log (spec §9.4). It matches the
  mum-breastfeeds / Oma-bottles reality and needs no protocol change. Accepted
  wrinkle: it is per device, not per Baby.
- **Stated, not learned** — set explicitly in Settings, following the spec's
  "stated, never learned" precedent. The sheet never silently adopts the last
  logged feed.
- **`other` drops out of the feed sheet's contents row** — the row is
  Breast milk / Formula only. `other` stays in the `BottleContents` domain type
  and remains selectable in the entry edit sheet, which keeps its own select
  (including "unsaid"), so old entries stay editable and displayable.

## Agent Brief

**Category:** enhancement
**Summary:** Configurable feed-sheet defaults (mode + bottle contents) as a Device Setting, and bottle contents as a segmented button row

**Current behavior:**
The feed sheet always opens in Breast mode, with bottle contents defaulting to
breast milk. Contents is a `<select>` (Breast milk / Formula / Other) placed
below the volume inputs. There is no way to make the sheet open on Bottle or
preselect Formula. Settings already renders a per-device section (the
appearance override) backed by the Device Settings module, which stores
plain-string values in localStorage and never syncs.

**Desired behavior:**

- A "feeding default" Device Setting exists with the states: breast (the
  seeded default, matching today's behavior), bottle with breast milk, or
  bottle with formula. Devices that have never set it behave exactly as today.
- The feed sheet opens with mode and contents preselected from this setting.
  The FAB-fan entry point and any "feed while asleep" path get the same
  preselection. Explicitly choosing a different mode or contents inside the
  sheet is a one-tap, session-local override — it does not write the setting.
- Settings gains a control for this default in the per-device section, using
  the same segmented style as the appearance control, and states (like other
  Device Settings) that it applies to this device only.
- In the feed sheet's Bottle mode, contents is a segmented button row —
  Breast milk / Formula — rendered directly under the Breast / Bottle / Food
  switch, replacing the `<select>`. The row follows the existing segmented
  pattern (the Left / Right / Both side row): `role="tablist"`, translated
  labels for EN / DE / RO via the existing message catalogue.
- The entry edit sheet is untouched: it keeps its own contents select with
  `unsaid` and `other`, so existing entries with `contents: 'other'` or null
  remain editable and correctly labelled.

**Key interfaces:**

- The Device Settings module (`blb.*` localStorage keys, read/write helpers
  with the private-mode try/catch) — add a getter/setter pair for the feeding
  default, following the appearance-override shape: a small string union, with
  unknown stored values falling back to the seeded default.
- The feed sheet's `mode` and `contents` state — initialised from the Device
  Setting instead of literals.
- The Settings page's per-device section — one new segmented control.
- New i18n messages for the setting's label and options in all three locales.

**Acceptance criteria:**

- [ ] With no stored setting, the feed sheet opens on Breast with contents
      breast milk — byte-for-byte today's behavior.
- [ ] After choosing "Bottle — formula" in Settings, opening the feed sheet
      lands on Bottle with Formula preselected; saving without touching either
      logs a formula bottle.
- [ ] Changing mode or contents inside the sheet affects only that entry; the
      stored default is unchanged afterwards.
- [ ] Contents renders as a two-button segmented row directly under the
      Breast / Bottle / Food switch; no `<select>` remains in the feed sheet's
      Bottle mode.
- [ ] The setting never appears in the sync log or the replica — verified the
      same way other Device Settings are (localStorage only).
- [ ] The entry edit sheet still offers unsaid / breast milk / formula / other
      and renders `other` on old entries.
- [ ] Unit tests cover the new Device Setting helpers (fallback on unknown
      values) and the sheet's initial state for each stored value, in the
      style of the existing client tests.
- [ ] Labels exist in EN, DE and RO.

**Out of scope:**

- Any synced/Household representation of the default, per-Baby defaults, or a
  layered override scheme.
- Learning the default from logged feeds.
- `other` as a button in the feed sheet's contents row.
- Netto/brutto formula volumes — that is issue 22.
- Changes to Food mode or the meal flow.

## Answer

Built as specified. `feedingDefault()` / `setFeedingDefault()` live beside the
appearance override in the Device Settings module (`blb.feedingDefault`,
unknown values fall back to `breast`); the feed sheet initialises `mode` and
`contents` from it on open, covering the FAB fan and the feed-while-asleep
path alike, and never writes it back. Contents is a two-button segmented row
(Breast milk / Formula) directly under the Breast / Bottle / Food switch — no
`<select>` remains in the feed sheet — while the entry edit sheet keeps its
four-option select. Settings gained the control in the per-device section
with a this-device-only hint; spec §9.4's table now lists it as the fourth
Device Setting. Labels in EN/DE/RO; tests in `device.test.ts` and
`feed-sheet.test.ts`.
