# A copy is logged now, and holding a row opens it

An Entry's sheet has a **Duplicate** button. It turns the sheet into the draft of a new Entry, with the same type and the same Baby: the values the sheet shows, the date and time reset to now, and a Session's end left empty. *Create copy* logs it as an ordinary creation, attributed to whoever pressed it and linked to nothing. The row it came from is not touched. Holding a timeline row opens its sheet already on that draft.

The use is "the same again": the 150 ml of formula she has every afternoon, or yesterday's lunch. That is why the copy is timed **now** and not at the original's time. A copy at the same instant is a second record of one event, and for a Sleep it is an open contradiction that the Session Merge folds away anyway. When the copy belongs somewhere else, the date and time are right there in the draft.

## Consequences

- **A copy starts the way the fan starts one.** A Session's end is left empty, so a copied bottle, breast feed, Sleep or stretch of tummy time is a Live Session. The fan's own new bottle is always running, and a 20-minute nap copied to now does not know when it will end. Typing an end in the draft writes a finished one. Any length copied over from the original would be data nobody entered. A running Sleep copied while she is already asleep is the contradiction the Session Merge exists for, and it folds into the Sleep that is running ([ADR-0014](0014-only-sleeps-merge.md)).
- **It is a feeding like any other** ([ADR-0019](0019-a-new-feed-ends-the-running-one.md)). A copied Feed or Meal ends the running Feed, and a copied Meal wakes her, each only from inside what is running. The draft says so with the feed sheet's inline lines.
- **What it copies is what the sheet shows, at the moment *Create copy* is pressed.** A bottle carries its Intake, so a legacy row's stored leftover never travels ([ADR-0018](0018-a-bottle-records-the-intake.md)). A Meal carries its Foods and amounts but not its reactions, because a reaction is what followed that one Meal. A copied rash would be a false entry in the export a doctor reads. The note travels, and it sits in the draft where it can be cleared.
- **A Measurement is never copied.** It is a reading of her on one day, and the sheet cannot change its numbers before they are saved.
- **The draft names itself in the title and on the button.** The title reads *Duplicate Meal* and the Save button *Create copy*. The first version only changed the title, to *Meal again*, and that was overlooked on the long-press above all: there the sheet opens with no press on Duplicate to announce it, and looks like the edit sheet it was opened from. A panel saying *"New entry, copied from …"* was tried and dropped, because nothing exists until *Create copy* is pressed, and the draft must not say it does.
- **Logging asks nothing.** *Create copy* writes straight through, even when the source row is days old. The old-row question of [ADR-0042](0042-an-old-correction-asks-once.md) protects corrections to the past, and a copy corrects nothing.
- **Holding is a shortcut, never the only door.** The spec rejected a 400 ms long-press for the poop because nobody finds one at 3am (spec §8.5). That still holds, so Duplicate is a visible button, and the hold only saves the tap that opens the sheet. A stray hold while scrolling writes nothing, because the draft still needs *Create copy*. The row no longer starts a text selection or the system callout when held. The context-menu gesture (a right click, the menu key, Android's own long-press) counts as the hold, and the click that ends a hold reaches nothing.
