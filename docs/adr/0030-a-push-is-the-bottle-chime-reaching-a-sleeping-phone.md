# A push is the Bottle Chime reaching a sleeping phone

The deployment sends one kind of push notification: the **Bottle Chime**, ten minutes before a started bottle's Life runs out, to the Devices that switched it on. Nothing else notifies — not an overdue Feed, not a Wake Window, not a Stale Session. This exists because [ADR-0029](0029-the-bottle-chime-is-a-device-setting.md) shipped a reminder that only worked on a phone that happened to be awake with the app open, and ten minutes before a bottle's Life runs out is very often neither: the web gives a page no way to wake itself while the phone is asleep, so a chime that only sounds in the foreground is a chime that misses the case it was built for. A push is the only mechanism that reaches a locked screen, and the notification's own sound is the phone's, which is what actually gets through.

The instant is not computed a second time. `bottlesNearingEnd` — the domain fold the timeline already uses — is imported by the server unchanged, so the client and the notifier can only ever agree, which is the promise [ADR-0006](0006-targets-are-stated-not-learned.md) made when it put the due-instant computation in one module.

## Consequences

- **The subscription is the setting.** There is no server-side notification preference. A row in `push_subscriptions` exists exactly while that phone's Bottle Chime is on and its browser has granted permission; switching the chime off deletes it on both sides, signing out deletes it, and being removed from the Household deletes it — a notification is access, and access is what removal ends. The spec's standing instruction not to hang a `notify` flag off Member (§2) is kept by having no flag at all.
- **The payload is encrypted to the Device, and the Baby's name is in it.** RFC 8291 is not decoration here: a push travels through Google's or Apple's servers, and they forward ciphertext they cannot read. That is what makes it safe for the notification to say *Lina's bottle* rather than something coy that has to be opened to be understood. The keys come from the browser and never leave the deployment.
- **Written against the RFCs, not pulled from a library.** ECDH, two HKDFs, one AES-GCM record, an ES256 JWT — every primitive is in `node:crypto`, and the repo keeps one runtime dependency. The test decrypts from the *receiver's* side, which is the direction RFC 8291 is written in, so a derivation that agreed only with itself comes apart there.
- **The VAPID keypair lives in the volume**, beside the session key and generated on first boot for the same reason: the operator configures nothing, and no environment variable is added. Losing it costs every Device its subscription — a browser refuses a push signed by a stranger — which is recovered by switching the chime off and on again, and is a smaller loss than the session key's.
- **A timer, at last.** [ADR-0017](0017-a-bottle-past-its-life-ends-its-own-feed.md) could say "there is no timer; while nobody pushes or pulls, nothing happens" because a bottle closing late still closed at the right instant. A *notification* has no such luxury — late is worthless — so the server now ticks every thirty seconds. It is unref'd like the nightly backup, it looks at nothing when no Device is subscribed, and it is deliberately not where past bottles are closed: that rule stays where it was, in the push and pull path.
- **Said once per bottle per Device.** `push_sent` records only what was *delivered*, so a push service having a bad minute is retried on the next tick — and only while the bottle is still inside its last ten minutes. A 404 or 410 deletes the subscription; nothing else does.
- **On an iPhone it needs the app installed**, which is what the v1 install nudge was already for. Settings says so rather than failing silently: the switch reports what the browser allowed — woken when closed, blocked, or this-browser-cannot — because a chime that can only sound in the foreground is a different promise from one that wakes the phone, and a Member has to know which one they have.
- **It stops at the notification.** No action buttons, no *offer the rest* that logs something, no badge count. Tapping opens the timeline, where the row states the exact figure. The app still never invents a value.
- **One deployment, many Households, one worker file.** The service worker has no locale of its own, so the text is composed on the server in the Member's own language and displayed verbatim.
