# A Hub is a Device, and its reads are derived

A **Hub** — a Home Assistant instance, or anything else that watches a Household from a screen on a wall — gets in exactly as a phone does: it claims a Claim Link, it holds a session, and it writes by pushing revisions to the one write path there is ([ADR-0005](0005-claim-links-instead-of-passwords.md), [ADR-0003](0003-revisions-are-the-sync-unit.md)). What it does **not** get is a replica. It holds no log, folds nothing, and cannot answer *when did she last feed* from anything it has; so it reads one **derived** endpoint that computes nothing of its own — `headerState` and `statsFor`, the app's own folds, run server-side the way `notify.ts` already runs them. The alternatives both cost more than they look. Teaching a hub to fold the revision log means a second implementation of merge redirects, day bucketing and the Targets, in another language, drifting from the first the week either changes. Giving it an action API means *start a feed* meaning something in two places, and the one that is not the app is the one nobody tests at 3am.

This is not a second sync path, and the distinction is the whole load-bearing part: **the derived endpoint ships no rows**. The pull remains the only way a Revision reaches anyone, the replica remains the app's only source, and the app itself never calls this endpoint. What travels is a projection — the same numbers the sticky header prints, addressed to a client that cannot compute them.

## Consequences

- **Nothing new is invented for authentication, and the Hub is Removed rather than expired.** A hub is claimed as its own Member in the Caregiver role, so attribution stays honest — a button on a kitchen wall is pressed by whoever is standing at it, and *Home Assistant* is the true answer — and so removal unplugs the hall panel without signing anyone's phone out. A hub session does not expire: [ADR-0005](0005-claim-links-instead-of-passwords.md) refused a timer because it signs Oma out when re-authentication is hardest, and while that reason does not describe a hub, an expiry that applies to some Devices and not others is a second auth model in the first one's clothes. Revocation is the control here as everywhere.
- **The Caregiver role is the blast radius, deliberately.** The credential sits at rest on a box in a hall, against a public origin. `refuseByRole` lets it log and correct Entries and grow the Food catalogue; it refuses deleting an Entry outside the writer's own undo window, managing Members or Babies, and changing Household settings or Targets. A stolen hub can write a feed that never happened. It cannot erase the timeline, cannot open the door to another Device, and cannot move a Target the rest of the Household reads.
- **[ADR-0019](0019-a-new-feed-ends-the-running-one.md) moves into the push transaction.** *A Baby eats one thing at a time* is enforced today in the feed sheet, which means it is enforced for one writer. Session Merge and the bottle past its Life already live inside `push()`; this joins them, guard unchanged. It is a fix rather than a concession — two Devices starting a Feed already reach the same hole — and it is what lets a Hub write a plain creation and get the rule for free. **A rule the server does not hold is a rule only the app has.**
- **The derived endpoint is conditional from the first commit.** A phone disconnects; a hub never does, and [ADR-0021](0021-the-paid-service-scales-by-files-not-by-postgres.md) plans hundreds of Households in one process holding idle SSE connections. The response carries the Household's cursor and answers `If-None-Match` with a `304`, so a quiet night costs a cursor lookup rather than a fold over a week. Refresh is driven by the existing SSE wake signal; polling is the fallback, and reconnects carry jitter so a deploy does not bring the fleet back in one second.
- **A Lapsed Household refuses this endpoint too.** [ADR-0022](0022-a-lapsed-household-stops-syncing.md) allows no read-only tier, and a derived read added without that in mind quietly becomes one. It answers `lapsed` beside `unauthenticated` and `removed`, and the Hub is expected to say *hosting is paused* in its own idiom — the ADR's reason holds for a wall panel exactly as for a phone: stopping in silence reads as a bug.
- **The Hub's outbox is bounded, and the protocol makes it nearly free.** Push is insert-only with client-minted ids, so a retry after a lost response is a no-op; a press mints its revision id immediately and retries until it lands. Bounded and visible, because a hub is not a phone: silently queuing feeds for six hours is worse than saying it did not send. Merge keys still come from the writer's clock corrected by the observed server offset, so a hub that was cut off writes the same slightly-late revision a phone would, clamped and flagged rather than refused.
- **No CORS, ever, and no cross-site cookie.** A browser-side card calling this deployment directly would need the session cookie in a third-party context — weakening every Household's posture to serve one hub. A Hub reads and writes server-to-server; whatever it draws on a screen, it draws from itself. The app stays same-origin.
