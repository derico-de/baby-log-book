# A Milestone Name is written, not chosen

A Milestone stores the name as a plain string exactly as the Member typed it, and the combobox they type into is suggested from the distinct names this Household has already used, unioned with ten localised starter suggestions that are UI text and nothing more. We chose this over the two obvious alternatives — a stored key from a curated list, rendered through the EN/DE/RO catalogues, and a mutable Milestone Name catalogue mirroring the one [Food](../../CONTEXT.md) has — because a key cannot express "rolled off the sofa", and a catalogue's whole job is keeping many rows spelled alike, which does not apply to a name you type once in your life.

## Consequences

- **A mixed-language Household stores mixed-language names.** Papa on EN picks the suggestion "First tooth" and those words are stored; Bunica reads "First tooth" in her RO app. The presets look localised right up until one is picked, at which point it freezes into whichever language did the picking. This is already true of the Food catalogue and is accepted for the same reason: it is a name a person wrote, not a term the app owns.
- **No cross-household or cross-language figure can ever be computed** — "first tooth at 7 months" is not derivable from free text. Nothing in v1 asks, and v3's charts are about Measurements.
- **The suggestion list cannot drift, because it is not stored.** It is read off the Milestones themselves, which is the same argument [ADR-0001](0001-single-entries-table.md)'s model makes for deriving first exposure: correct a typo on the entry and the bad suggestion disappears with it, with no second cleanup. A catalogue would keep an orphan the moment its last Milestone was deleted.
- **Uniqueness stays the parent's business.** Exact string match is enough identity to *derive* that "first tooth" is already logged for a Baby, but the model never enforces or warns, because it cannot tell a once-only name from "new word" and "new tooth" without the per-name flag this decision rejects — so any warning would be right on the firsts and wrong on every repeat.
- **The starter suggestions carry no ages and are not filtered by the Baby's age**, though the birth date is available. Ordering them roughly chronologically is a convenience; attaching "7–10 months" would make a logging app into a developmental schedule, which is the line [ADR-0006](0006-targets-are-stated-not-learned.md) already draws.
